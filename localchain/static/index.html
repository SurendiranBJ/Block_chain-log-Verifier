Ready for additional nodes
Add observer nodes using the same genesis file and a unique node data directory. Connect them with an approved enode address and add their RPC endpoints to peer_rpcs in runtime/chain.json.
Observers replicate the chain. They are not additional validators. Validator membership changes require Clique voting and should be planned separately.
A single validator provides tamper evidence while its key and chain data remain trusted. Independent peers and retained external checkpoints strengthen that trust boundary.

01 / CONNECT YOUR PROJECT
Watch a log file
Create an account and choose your existing project's log file. Download the agent and connection config. In the folder containing those downloads, run:
python3 logchain-agent.py --config logchain-connection.json
Keep your application, this agent and LogChain running. The agent reads your file every two seconds. It forwards new records and mirrors edits, deletions and restorations. The dashboard refreshes automatically.
Plain text and generic JSON Lines use stable line numbers. Do not rotate, replace or insert lines into an existing stream as routine operation: register a new source for each rotated file. Structured JSON events should have stable event IDs and increasing sequence numbers.
Source offline?
A disconnected agent makes external content unavailable after 15 seconds. Last known records remain visible; reconnection resumes monitoring. A missing or malformed file is reported as unavailable rather than an empty, clean file.
02 / CONNECT FROM APPLICATION CODE
Send events directly
Choose API integration during source setup. Use the provided source URL and token in your backend. Send each event once, or retry unchanged events safely.
POST /api/sources/SOURCE_ID/events
Authorization: Bearer SOURCE_TOKEN
Content-Type: application/json

{"events":[{
  "event_id":"evt-001", "sequence":1,
  "timestamp":"2026-11-04T12:00:00Z",
  "actor":"student-42", "action":"login",
  "message":"User signed in"
}]}
Direct event ingestion monitors the copy received by LogChain. To detect later changes in your project's original file, use the file agent.
What verification means
Original contents are stored in your isolated workspace; SHA-256 commitments and observations are anchored on the shared private chain. Observed changes and restorations stay in the timeline. A change made and restored entirely between agent reads may be missed. LogChain cannot prove a log was truthful before its first receipt.
This local setup accepts connections on this computer only. Independent peer nodes strengthen retained blockchain evidence; one validator still depends on its signing key and chain data remaining trusted.
